# Changelog

All notable changes to the Quadrate programming language are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`d128` — IEEE 754-2008 decimal128.** A primitive type with 34 significant decimal digits, written with a `d`: `0.1d 0.2d +` is `0.3` and equals `0.3d`. `+ - * /`, `neg` and the comparisons take it; an `i64` widens to it exactly, in arithmetic, comparisons and arguments, while an `f64` does not mix (`cast<d128>` converts, correctly rounded from the `f64`'s binary value); it is held in the stack slot itself, sixteen bytes with nothing to release; it keeps the exponent a value was written with (`2.50d` prints as `2.50`), and works as a local, parameter, struct field, array element (`[]d128`, `[n]d128`), global, constant, closure capture and `switch` label. The arithmetic is libmpdec's, pinned by a wrap and linked into the runtime, so a compiled program needs nothing installed where it runs.
- **`quadc --default-float d128`**, and `qd_interp_set_default_float` for an embedder: a float literal written without a `d` is read as a `d128`, for a calculator where every number typed should be decimal. It applies to the files named, not the modules they import; integer literals stay `i64`.
- **`qd_args(ctx, op, sig, ...)`** pops all of a native word's arguments at once: `qd_args(ctx, "strings::substring", "sii", &s, &start, &length)`. It checks the whole signature before popping anything, so a type error or underflow raises with the stack untouched and nothing taken that would need releasing. Popping one argument at a time with `qd_arg_*` can't promise that once one of them is a string. The letter `v` takes a value of any type, as a stack element. Every stdlib module with native words uses it, the freestanding `mem` among them (the freestanding runtime has a `qd_args` and a `qd_fatal_raise` that halt), as do `len`, `nth`, `set`, `append` and the `[n]T` arrays.
- **`qd_fail(ctx, code, fmt, ...)`** is how a fallible native word fails: `return qd_fail(ctx, IO_ERR_NOT_FOUND, "io::open: %s", strerror(errno))`. It sets `error_code` and the message, pushes the code as the word's status, and returns it. A word needs all of that, and words that did it by hand left out one part or another (see Fixed). The `os` and `thread` modules use it throughout.
- **`examples/decimal`**: compound interest in `d128`, rounded to cents with ties to even.
- **`quadlint --source-path <path>`**: lint the one file given as if it were at `path`, so an editor linting an unsaved copy is checked against the real neighbouring files.
- **`decimal` module**: the IEEE operations beyond the operators — `fma`, `remainder`, `fmod`, `round_even`, `quantize`, `reduce`, `scaleb`, `logb`, `next_up`, `next_down`, `min`/`max` (minNum/maxNum), `total_order`, the classification predicates — and `sqrt`, `exp`, `ln`, `log10`, `pow` and the trigonometric functions. The trigonometric functions reduce against 6,400 stored digits of pi, so `sin` of 1e6144 is as accurate as `sin` of 1.
- **`strconv::parse_d128`**, fallible, taking the whole string or nothing.
- **`sb::append_value`**, which appends any value as `cast<str>` spells it.
- **Exponent notation for floats**: `1e3`, `1.5e-3` and `6.02214076e23`; a point or an exponent makes a literal an `f64`, the point needs a digit on each side (`5.` and `.5` report the float that was meant), and a literal too large for an f64 is an error.
- **`clone`**: a shallow copy of a struct — same type, fields copied, what a field points to shared — rejected where the struct type is not known.
- **Nested array types**: `[][]i64` is a type, `[n][]i64` builds one filled with distinct empty arrays, and qualified element types like `[]mod::Point` have a spelling. Every type position now reads every type form through one `parseTypeFrom`; nesting past 64 deep is rejected.
- **`[n]T` array literals, replacing the `make` family**: `[10]i64` is ten zeros, `[2]Point` two distinct instances rather than two nulls, `[]i64` an empty array. A type name hard against the `]` makes the brackets a size; `[10]` is still one element.
- **Array-typed struct field defaults**: `struct Bag { xs:[]i64 = []i64 }` and `Bag {}` work, so an array-holding struct can be default-constructed.
- **`fuzz_formatter` and `fuzz_lsp_text`**: the two fuzz targets `tests/fuzz/meson.build` had always named but which were never written; `tests/run_all.sh --suite fuzz` now runs all three.
- **`error` — errors as values (R24)**: `error::last` packs the `err` channel into an `Error` struct, `wrap` composes context, `root` walks the cause chain. The channel is unchanged, so `error::last` has to run first in the failure arm.
- **`docscheck` checks 1,010 of the documented examples, up from 219.**
- **Specification §11.2.2, "Ownership"**: who retains and who releases, which §11 never said.
- **`memory` suite case `holders`**: an array of strings, an array of structs, a closure's captured block, a deferred block, a generic struct field and a plain string field, each built and dropped 20,000 times.
- **`memory` suite case `global_var_store`**: a `str` global and a struct global reassigned 30,000 times, which is the only way to see a leak the pointer registry keeps reachable.
- **`mem::set_any`, `mem::get_any`, `mem::clear_any` and `mem::AnySize`**: a slot that carries a value's type with it — eight bytes of payload and eight of tag.
- **`json::parse` — a real JSON parser.**
- **`tests/run_memory_test.sh`** (suite `memory`, test `memory_test`): three programs built and dropped at two iteration counts a hundredfold apart, failing if peak RSS grows by more than 4 MB between them.
- **`stack fn` — a function whose arguments stay on the stack.**
- **`while` and `until` — conditional exits inside a loop.** Each takes a flag and leaves the innermost `loop` or `for`: `while` when the flag is false, `until` when it is true. `loop { i n < while ... }` is a loop tested first, `loop { ... done until }` one tested last, and the test can sit anywhere in between. Each is a word with the effect `( flag -- )`, so the condition is whatever precedes it and values pending on the stack under the loop are left alone. This replaces the `cond while { body }` form, whose condition was found by scanning backwards and had to account for the whole stack, so no value could be pending where a loop was written (R54, R78). The interpreter, which never ran that form, runs these.
- **`strings::byte_len`**, the size of a string's UTF-8 encoding.
- **`math::inf`, `math::nan`, `math::is_nan`, `math::is_inf`, `math::is_finite`.**
- **`print` renders arrays.**
- **Exhaustiveness warning for a `switch` over an enum.**
- **`sort::by`, `sort::is_sorted_by` and `sort::lower_bound_by`**: sorting, checking and binary search ordered by a caller-supplied comparator, using C's `qsort` convention.
- **Function-pointer tests** for dispatch through a struct field and through a declared parameter, plus rejections for a signature mismatch and an unconsumed result.
- **Generics tests** for `[]T`, `fn(T -- T)` and a returned `Box<T>`, through plain and module-qualified calls, plus rejections for a binding conflict and a parameter mismatch.
- **`switch` arm stack-effect rule** (spec §6.5.1).
- **`qd_stack_truncate(ctx, target)`** in `libqdrt`, and a matching freestanding stub.
- Regression tests pinning the checks that a call in the body used to switch off — arity, `if`-arm balance and `defer` effect — and the stack rules for the arms of a fallible call.
- **fish completions** (`completions/quad.fish`), covering all ten tools with per-option descriptions, subcommand dispatch for `quad` and `quadpm`, and passthrough.
- **zsh completions** (`completions/_quad`), covering all ten tools with per-option descriptions, `.qd`-filtered file arguments, subcommand dispatch and passthrough.
- **`quaddoc` reports files it could not parse**, as `file:line:column: warning: ...`, and carries on documenting what did parse.
- **`qdcli::Help`** (`lib/cli/src/help.cc`): a shared renderer for the tools' `--help` pages.
- **`tests/run_cli_surface_test.sh`** (suite `tools`, test `cli_surface_test`): 277 checks pinning what all ten tools share — `--help` shape, `--version` format, how a bad option is reported, and that the bash completions list every documented option.
- **`completions/quad.bash` rewritten** against the tools' actual flags, and covered by `cli_surface_test`.
- **Long forms for `quadc`'s short options**: `--output`, `--debug`, `--stack-size`, `--include` and `--module`, and `--output` for `quaddoc`'s `-o`.
- **`--no-color` on `quad` and `quadmcp`**, the last two tools that rejected it.
- **`BaseOptions::optionError`**: lets a tool's option handler say what was actually wrong with a flag instead of falling back to "unknown option".
- **`SemanticValidator::finalStackTypes()`, `finalStackStructTypes()` and `finalStackFunction()`**: what the most recently type-checked function body leaves on the stack.
- **`quadrepl` `:doc <name>`**: shows a name's stack effect, for builtins, keywords, standard library functions and functions defined earlier in the session.
- **`quadrepl` command aliases**: `:quit` and `:exit`, and `:save`/`:load` alongside `.save`/`.load`.

### Changed

- **One module search** (`lib/qc`'s `module_resolver.h`), which quadc, the validator, quadlsp, quadrepl and quadpm all run, in the order specification §9.2 now gives. Each kept its own copy, and they disagreed: see Fixed. A module is every `.qd` file in its directory; the validator alone used to read only `module.qd` when there was one.
- **A stdlib error can be recovered from.** About 470 places in the stdlib reported a fatal error with `fprintf` and `abort()`, which an embedder that had armed recovery -- the REPL among them -- could not survive: `42` handed to `strings::upper` through an `any` killed the session with signal 6. They now raise through `qd_fatal_raise`, and the message names the word and the type: `strings::upper: Expected string, got i64`.
- **`qd_arg_i`, `qd_arg_f`, `qd_arg_d`, `qd_arg_p`, `qd_arg_s` and `qd_type_name`** in `libqdrt`: pop a native word's argument as a type, or raise naming the word. `math`, `decimal` and `unicode` use them in place of their own copies; `math.c` went from 948 lines to about 170, and the fifteen words that read any value as an `f64` without checking its type now check it.
- **`bool` is an alias for `i64` wherever a type is written**: parameters, results, `[]bool`, `[n]bool` and fields, where before it was accepted in a struct field and nowhere else.
- **`cast<f32>` and `cast<string>` are errors.** Neither `f32` nor `string` is a type anywhere else; the casts are `cast<f64>` and `cast<str>`.
- **One list of type names and one of keywords.** `lib/qc`'s `type_names.h` and the keywords in `reference.def` are what the compiler, `quadlsp`, `quadrepl` and `quaduses` read, where each kept a copy and the copies disagreed.
- **`sizeof` takes a type.** `sizeof<T>` is the size of a type; a bare `sizeof`, which popped a value and pushed 8 whatever it was, is a compile-time error.
- **`quadlsp` runs the `quadlint` built beside it** before the one on `PATH`, and checks an open file against the same neighbouring files `quadc` merges: not files with their own `main()`, not `*_test.qd`, none under `tests/`.
- **u8t tokenizer updated to 1.4.2**: one number scanner upstream instead of two near-identical copies. The token stream is unchanged over the test corpus and 200k random numeric inputs.
- **`sort` takes arrays, and only arrays.** All sixteen entry points take a `[]T`; the numeric ones took a raw `mem::alloc` buffer and a `count` beside it, so `[5 2 8 1 9]` could not be sorted by anything.
- **The `strings` FFI drops the count beside the array.** `sort`, `sort_desc`, `join` and `column` take a `[]str` and read its length; `split`, `split_n`, `lines` and `words` return the array alone. The two spellings for one job are gone — `strs count strings::sort` is `strs strings::sort` — and `words` over a string with no words returns an empty array rather than null.
- **`ct`'s containers write through the receiver instead of returning a new struct.** `Vec::push`/`pop`/`set`/`reset`, `Deque`'s four ends, `Queue::enqueue`/`dequeue`, `Map::insert`/`remove` and `Set::add`/`remove` return the container they were called on, and `release` clears the fields so a second one is a no-op.
- **`stdlib/regex` appends states instead of preallocating 256 null slots**, which cost 256 slots per compiled regex and left the unfilled ones as nulls.
- **`stdlib/regex` represents its NFA as typed structs rather than raw byte offsets**: `State`, `Nfa` and `Parser` records replace forty lines of hand-computed offset constants and their accessors.
- **`and`, `or` and `not` are logical; the bitwise operations moved to `bits` (R13).** `2 1 and` is `1` now, not `0`; the bitwise forms are `bits::and`, `bits::or`, `bits::xor` and `bits::not`, each an `inline stack fn` over one instruction. `lnot` is gone. This does not add short-circuiting, and R13 is closed anyway: the corpus has no site that needs it.
- **Two dialects, spelled explicitly.** Binding is the unmarked default and `stack fn` marks the function whose inputs stay on the stack; the choice per function is a readability judgement. 48 of 452 functions that take parameters are `stack fn`.
- **A sized integer type is rejected where it has no width to describe.**
- **`printsv` is removed.**
- **`pick` copies the third value and no longer takes an index; `roll` is gone.**
- **`strings::char_at` is total: an index outside the string is `strings::NotAChar` (-1), not an error.**
- **`unicode` is now actually Unicode, and keeps its name.**
- **`unicode::is_ident_start` and `is_ident_cont` are pinned to ASCII.**
- **`str` is genuinely UTF-8, and its unit is the codepoint.**
- **No string operation can produce invalid UTF-8 any more.**
- **Case mapping covers the cased scripts, not just ASCII.**
- **`is_alpha`, `is_alphanumeric` and the trim family are per codepoint.**
- **`cast<T>` no longer converts a string to a number; that direction is a compile error.**
- **Float division by zero follows IEEE 754 instead of aborting.**
- **Array literal elements may be any single-value expression.**
- **The element type of an array literal is inferred from all of its elements**, not just from element zero.
- **Specification §11.2.1, "Reference Cycles"**: reference counting alone must not be expected to reclaim a cycle, and this implementation provides neither a cycle detector nor weak references.
- **`hof` is generic.**
- **Arrays decide their element type on first use.**
- **The function-level output check compares pointer types structurally**, with the function's own type parameters as wildcards.
- **A function pointer can be called through a struct field or a declared parameter.**
- **`call` no longer switches off the function-level checks.**
- **A function pointer is checked against the field it initialises.**
- **`buildFnTypeString` renders declared type names**, so a function returning a struct is `fn( -- Point)` rather than `fn( -- ptr)`.
- **Generic type parameters unify structurally, so `[]T` and `fn(T -- T)` work.**
- **A type parameter used twice must bind to one type.**
- **Module-qualified calls check their argument types.**
- **An instantiated generic struct keeps its type arguments.**
- **`ident <<field` is no longer folded by the parser.**
- **The declared-effect, `if`-arm and `defer` checks now run in functions that call other functions.**
- **A failure arm is modelled from the pre-call stack, and a `drop` in it is a compile error.**
- **The success arm of a fallible `if` must leave the same depth as the failure arm.**
- **A fallible function's failure exit truncates the stack to what the caller expects**— the depth at entry minus the declared inputs and receiver.
- **Balanced `if`/`else` arms now yield the arms' types, not the pre-`if` types.**
- **A block diverges when any top-level statement in it is `panic`, `return`, `break` or `continue`**— not only when the last one is.
- **A fallible *method* call before an `if`/`switch` is recognised as one.**
- **Module functions with no declared outputs produce nothing.**
- **Generic type parameters are skipped in method-call argument checks.**
- **Diagnostics** for the `if` rule report the arms' resulting depths (`then: 2 value(s), else: 1 value(s)`) and carry a hint after a fallible call.
- **`quaddoc` reads declarations from the compiler's AST.**
- **Parameter tables describe the parameters the function actually has.**
- **Every tool's `--help` follows one layout**: `<tool> - <summary>`, a description paragraph, `Usage:`, an `Options:` block opening with `-h`/`-v`/`--no-color`, tool-specific sections, then `Examples:`.
- **Compiler diagnostics drop the `quadc: ` prefix** when they carry a source location.
- **`quadpm`'s diagnostics match the other tools.**
- **`quadmcp --version`** reports `quadmcp <version> (<commit>, built <date>)` like its siblings.
- **`quadlint` reports a bad option value once.**
- **`quadc` with no arguments** reports `quadc: no input files` on stderr and exits 1.
- **`quadrepl` keeps values on the stack.**
- **`quadrepl` tab completion reads the standard library from disk.**
- **`quadrepl` compiles and runs each line once.**
- **`quadrepl` accepts `struct`, `enum`, `const`, `type` and `var` declarations.**

### Fixed

- **`break` and `continue` in a `switch` with no loop around it compiled to nothing.** The checker counted a `switch` as a loop, but neither backend does: in a `switch` inside a loop both act on the loop, and with no loop there was nowhere to jump, so the code after a `break` ran as if it were not there. It is now an error, `'break' not within a loop`, as it is for `while` and `until`.
- **Compile-error tests whose expectation file had no trailing newline checked nothing.** `tests/run_all.sh` read the patterns with `while read`, which skips a last line without a newline, so 32 of the 249 `.err` and `.runtime_err` files passed whatever the compiler said. Six of them had gone stale and now say what the compiler says, and `multiple_errors` moves its undefined name into a function of its own, since past one the checker stops trusting that function's stack model and did not report the underflow the test expects.
- **`0 strings::from_char` gave the empty string.** The character was pushed as a C string, which ends at its first NUL; it is now the one-byte string holding NUL.
- **A `switch` on a string leaked the string when the matching arm returned or broke out.** The value was released after the switch, which such an arm never reaches; it is now released as the arm is entered.
- **A string `switch` label matched a string holding a NUL byte by its part before the NUL.** The label is now compared with the whole string, so `0 strings::from_char` no longer matches `""`.
- **The language server offered no fields after `p <<`.** It looked for the variable only directly before `<<`, as `p<<`, and gave up when the document did not parse, which it never does while the field name is still to be typed.
- **The language server dropped all of the document's own functions and structs while the document had a parse error.** Completion, semantic tokens, inlay hints, code lens, linked editing and the call and type hierarchies saw none of them; what did parse is now used.
- **`qd_build` compiled a script with syntax errors.** It never checked for parse errors, so a function that did not parse was dropped without a word and the rest built. The errors are now printed and the build fails.
- **`qd_build` reported errors two lines below where they were.** It put a `package` line, which is not Quadrate, ahead of the script; it no longer does.
- **Building a module a second time leaked the first build's library and temporary directory.**
- **A method called as `module::method` did not cast its arguments.** `p 2 geo::scale`, with an f64 parameter, stopped on a type mismatch at run time, where `p 2 scale` cast the 2.
- **A bare fallible method called as `module::method` was not required to be checked.** It now gets the "must be immediately followed by 'if' or 'switch'" error the other forms of call get, instead of a stack-depth error about whatever function it was in.
- **A struct field stored an i64 or f64 value of the other type as its raw bits.** `S { f = 2 }` with `f:f64` read back as 9.88e-324, and `s 2.5 >>y` and `2.5 S` with `y:i64` as 4612811918334230528; the validator called each an implicit cast, and nothing cast. Named construction, positional construction (`x y Point`, `x y mod::Point`) and `>>field` now convert, and an `any` is checked as it is stored. Positional construction also rejected an `i64` for a `d128` field and an `any` for any field, which named construction takes; both forms now go through one check.
- **A field initializer was checked by a partial copy of the type checker.** It typed an expression by its first operand, so `y = 2 1.5 *` passed as an i64, and a call's result not at all, so a `str` went into an `i64` field as its address. `x = +` compiled and took whatever was beneath the construction, and `x = 1 2` passed. Each initializer is now checked as the code it is, on a stack of its own, and must leave one value.
- **An i64 in a d128 field is widened, as an i64 argument to a d128 parameter is.** It was a type error.
- **A closure that captured a parameter and outlived the call read a dead stack frame.** Parameters, and a method's receiver, lived on the machine stack whether or not a closure captured them; a captured one now lives in a refcounted block, as a captured `-> name` does.
- **A closure could not read a variable that only the closure around it could see.** The outer closure did not capture it, so the inner one was built with an uninitialised pointer and the call crashed. An enclosing closure now captures what the closures inside it need.
- **A closure's local captured by a closure inside it, and a variable captured in a `test` block, lived on the machine stack,** and releasing the closure wrote a refcount over the stack slot before it.
- **A closure parameter named like a variable outside it read the outside variable.** `5 -> n  fn (n:i64 -- r:i64) { n }` returned 5 whatever it was called with.
- **A module's method called without its receiver compiled.** `2.0 geo::scale` picked a method by name and failed at run time in `roll`; it is now an error that says what to push first.
- **`signal::wait` returned the same signal every time.** It did not clear the flag of the signal it returned, so with SIGUSR1 and then SIGUSR2 raised, both waits said SIGUSR1, and a `wait` loop spun on the first signal forever. It now takes the signal it returns. With no signal trapped, nothing could end a wait, and it is a runtime error rather than a hang.
- **`time::format` failed on a result over 255 bytes**, which strftime wrote into a fixed buffer. **`time::parse` ignored text after the date** (`"2024-01-15xyz"` parsed), and **failed on `1969-12-31 23:59:59`**, whose timestamp is the -1 that `timegm` also returns for failure. **`time::sleep` ended early** when a trapped signal arrived; it now sleeps out the rest.
- **The `mem` words failed silently.** A null address, a negative size or a wrong-typed argument set the error code to -1 and returned, pushing nothing, so `null 0 mem::get_i64` left the stack a value short and the program failed later, elsewhere. They now raise.
- **Compiled `null` was an i64.** The type checker and the interpreter have it as a ptr; compiled code pushed the integer 0, so a word checking for a ptr refused `null` as the wrong type, and `null print` printed `0` compiled and `null` in the REPL. It is a null ptr in both now, still equal to 0 and still matching `0` in a `switch`.
- **`mem::set_any` lost a d128's type.** A d128 is sixteen bytes and was copied over the slot's eight-byte tag, so `1.25d` read back as the integer 125. The slot now keeps a d128 in a copy of its own. `mem::to_string` and `mem::from_string` keep a NUL byte, and `from_string` of "" gives a buffer rather than reporting an allocation failure.
- **`log::log` with a level outside the constants read past a table of level names**; level 9 printed `[h^A   ]`. A level, format or rotation mode outside the module's constants now raises. A JSON log rotated at about twice its `max_size`, because the size counted for rotation left out everything the JSON writer escaped; it now uses the file's own size. `log::new` pushed nothing when it could not make a logger; the unused private `raw_log_kv` is gone.
- **`testing::assert_eq` reported the expected and actual values the wrong way round.** The expected value is the second, as in `2 3 + 5 testing::assert_eq`, but a failure printed the first as "expected"; `assert_approx_eq` did the same. A failure's report now also comes after what the test printed, and strings are compared whole, past a NUL byte. Too few values, or a value of the wrong type for `assert_approx_eq` or the string assertions, now raises like any other word rather than counting as a failed assertion; an i64 for `assert_approx_eq` widens to f64.
- **A `%` in a test's name was read as a format.** `quad test` printed each name through `printf`, so `test "keeps a long %s whole"` printed `(null)` in its place, and could crash. Names are printed as written.
- **`fmt::sprintf` and `fmt::fprintf` cut each value at 255 characters, and read past the end of their buffer to do it.** A `%s` with a 300-character string gave 256. The three format engines in `fmt` are now one, which builds each value to size.
- **`fmt::fprintf` could not be called as declared.** Its signature is `( fd:i64 format:str -- )`, format on top, but it took the fd from the top, so every such call failed; the documented example had them in yet another order. It now takes the values under the fd, as `printf` takes them under the format, and writes after whatever stdout and stderr still had buffered rather than before it.
- **`fmt` format errors read freed memory.** Each type error freed the arguments and then read one of them for the message. Arguments are now all checked before anything is popped, so an error leaves the stack as it was and names the argument: `Expected i64 for %d (argument 2), got str`. A length modifier such as `%lld` is accepted rather than doubled into an invalid spec, and `%f` takes an i64 too.
- **`strconv` parse words read the start of a string and ignored the rest.** `"12abc" strconv::atoi` gave 12, `" 42"` gave 42 and `"1.5x" strconv::parse_float` gave 1.5. As `parse_d128` already did, `atoi`, `parse_int` and `parse_float` now take the whole string as the number and fail on anything else. `parse_int` and `atoi` also read `-9223372036854775808`, which was out of range, and `parse_float` fails on a value too large for f64 rather than giving infinity. Failure messages quote the input: `strconv::atoi: not a number: "bad"`.
- **`strconv::format_float` lost digits.** It wrote six significant digits, so `1234567.0` came back as `"1.23457e+06"`, a different number. It now writes the shortest text that reads back as the same value, which `json` had worked out for itself; `json` now uses it.
- **An array error printed a line and carried on.** `nth` or `set` past the end, a negative size in `[n]T`, a value of the wrong type in `append` or `set`: each printed to stderr and returned -1, which compiled code does not read, so `xs 3 nth` on a three-element array pushed nothing and the program failed later, somewhere else. They now raise, as every other builtin does: `Fatal error in nth: Index 3 out of bounds (length 3)`. `[n]i64` and `[n]f64` arrays are now zeroed when they are made rather than by a loop after.
- **What a program printed before a runtime error came out after the error.** A raised error wrote to stderr while stdout still held earlier output in its buffer, so piped or captured output showed them in the wrong order. stdout is now flushed first, for raised errors, the inline stack-overflow check and a function's argument check (`qd_check_stack`, which now raises the same way and can be recovered from in the REPL).
- **`io::tell` left the handle on the stack.** It only peeked at it, though its signature consumes it, so the stack held one value more than the compiler thought.
- **`io::read_file` read a file under `/proc`, or a pipe, as empty.** It sized the file with `ftell`, which says 0 for both. It now reads to the end. It also kept only the text before a NUL byte, as did `write_file` and `append_file` and `io::readline`; they now keep it all.
- **`io::write_file` and `io::append_file` reported a full disk as success.** The data is often written only when the file is closed, and the close was not checked; writing to `/dev/full` said Ok. A failed close now fails the write.
- **`io` failures had the wrong code.** `io::open` said `ErrNotFound` for every failure, "Permission denied" included, and `write_file` said `ErrPermission` for every failure, a missing directory included. Codes now follow errno, and each message names the word: `io::write_file: No such file or directory`.
- **`net::send` and `tls::send` could end the program with SIGPIPE.** Writing to a peer that had gone raised SIGPIPE, which kills the process unless it is ignored. A send now fails instead. `net` sends with `MSG_NOSIGNAL`; OpenSSL writes with plain `write`, so `tls` blocks the signal around each write and takes back any it raised. Both now send all of the data, which may take several writes, and keep a NUL byte in it.
- **`net::set_timeout` and `net::set_keepalive` failures passed `!`.** They pushed a failure status but did not set the error, so `!` read success. `net::receive` cut its data at a NUL byte while reporting the full count, a port outside 0 to 65535 wrapped to another port, and a receive that timed out said `ErrReceive` rather than `ErrTimeout`. `net::connect` now resolves with `getaddrinfo`, so it reaches IPv6 hosts, and its message says why it failed: `net::connect: localhost:44444: Connection refused`.
- **An untrusted certificate was reported as `tls::ErrConnect`.** After a failed handshake, `tls` compared OpenSSL's error reason against certificate verify codes, which are numbered separately, so it never matched. It now asks for the verify result: an untrusted, expired or misnamed certificate is `ErrCertificate`, and the message gives OpenSSL's reason, as in `tls::connect: Certificate error: unable to get local issuer certificate`. `http::get` and `http::send` carry the same reason.
- **`tls::receive` failed with `ErrClosed` when the peer closed cleanly.** That is the end of the data; it now gives "" and 0, as `net::receive` does. It also cut its data at a NUL byte.
- **A push onto a full stack silently dropped the value.** Compiled code checks its inline integer pushes, but string, float, pointer and `d128` literals, local reads and every value a native word returns go through `qd_push_i` and its siblings, which returned -2 that no caller read. With `-s 4`, `1 2 3 "a" "b"` carried on with four values and no error. The push functions now raise the same stack overflow as compiled code, which the REPL catches as it catches any other runtime error. They still return 0, so `return qd_push_i(ctx, n)` in a native keeps working, and an embedder no longer needs to check them.
- **The `http` server lost a request body that arrived after its head.** It read the request with one `recv`, so a body in a later packet was empty in the handler, and a client that sent `Expect: 100-continue` (curl does for large bodies) waited for an answer that never came and then got its body ignored. The server now reads the head and then as many bytes as `Content-Length` gives, sends `100 Continue` when asked, and refuses a body over 1 MiB with 413 and a head over 8 KB with 431. A request with no header lines got 400; it is now served. A body is no longer cut at a NUL byte.
- **An `http` response head over 4 KB overran its buffer.** It was formatted into a fixed 4 KB array and sent at its full formatted length, so `http::set_header` with a long value sent stack memory and a broken head. Heads are now built to size.
- **`http::send` returned a chunked response with the chunk sizes in its body.** It sends HTTP/1.1 but never decoded `Transfer-Encoding: chunked`, which most servers use. It now decodes it, and treats a response as complete by its `Content-Length` or final chunk, failing with `ErrReceive` when the connection breaks before that.
- **`http::send` put no port in `Host`**, so a request to `http://example.com:8080/` named the wrong host to a virtual-hosting server, and it sent no `Content-Length` for an empty body. It also wrote the request with a single `write`, which may send only part of it. The client now speaks to the socket and the TLS layer directly, rather than through the `net` and `tls` words and the stack, and resolves hosts with `getaddrinfo`, so IPv6 works; `http` no longer needs `net`. Its failures now carry a message: `http::get: could not connect to 127.0.0.1:1`.
- **`http::header` and `http::set_header` let a value write further headers.** A line break in the value went into the head as it was. A line break, or a colon in the name, is now a runtime error, as is a line break in `http::method`.
- **The `http` server could die of SIGPIPE.** Its sends did not pass `MSG_NOSIGNAL`, so writing to a client that had hung up could end the whole process. They do now, and loop until all of the data is sent.
- **The mTLS test never ran.** `tests/run_mtls_test.sh` looked for the `tls` module in `lib/tls`, which it left when it moved to `stdlib/`, so it printed SKIP and exited 0, which `run_all.sh` counted as a pass. It now finds the module in `dist/`, trusts its test CA, and requires the handshake with the client certificate to succeed; before, a failed one passed too.
- **Most `os` failures read as success.** `delete`, `rename`, `copy`, `mkdir`, `list`, `rmdir`, `walk` and `popen` reported a failure only through their C return value, which nothing reads. `"missing" os::delete!` carried on as if the file had gone, and an `if` took the success branch. They now fail like every other fallible word, with the cause as the message (`os::delete: No such file or directory`).
- **A failing `thread` word cost the caller a value.** The fallible `thread` words set the error but pushed no status, and the generated code drops one after the call, so `m lock?` on a bad mutex dropped whatever was beneath it.
- **Output printed before a failed `!` call could vanish.** The abort ended the program without flushing stdout, so with output going to a pipe or a file, everything printed up to the failure was lost. It is now flushed, ahead of the error message.
- **`os::system` returned a wait status, not the exit status.** `"false" os::system` gave 256; it now gives 1, and -1 when the command was killed by a signal.
- **`os::glob` with no matches gave a null array**, so `entries len` on its result was fatal. It now gives an empty array.
- **A failed `os::list` left its two outputs under the status**, and always said `ErrNotFound`. It now leaves only the status, and says `ErrNotDirectory` for a file, as documented.
- **`os::rmdir` on a missing path succeeded**; it now fails with `ErrNotFound`, as documented.
- **`os::copy` ignored read errors and a failed close of the destination**, where a full disk can first show. Both now fail the copy.
- **An unexpected filesystem exception in `os` said `ErrPermission`.** It reported errno 1, which is `EPERM`; it now says `ErrIo`.
- **23 of the `strings` words never checked their arguments' types.** A wrong-typed value that reached one at run time was read as a string or an integer anyway. The 23 were `pad_left`, `pad_right`, `center`, `capitalize`, `title`, `trim_prefix`, `trim_suffix`, `replace_first`, `insert`, `remove_range`, `truncate`, `lines`, `words`, `split_n`, the six `is_*` classifiers, `byte_len`, `slice` and `column`. Every `strings` word now checks its whole signature and reports, for example, `Expected i64 for argument 2, got f64`. When one raises it now leaves the stack untouched instead of half-popped.
- **A send on an unbuffered channel didn't wait for a receiver.** `thread::chan_new` promised a synchronous channel but gave a buffer of one, so `send!` returned as soon as the value was stored. It now returns once another thread has received the value. If the channel is closed first, the send fails with `ErrClosed` and takes its value back, so a failed send never delivers. `try_send` on an unbuffered channel now succeeds only when a receiver is already waiting.
- **The `thread` words quietly ignored a wrong-typed argument.** `wg_add`, `once_do`, `sleep` and the `free` words popped it and did nothing. `is_alive`, `try_lock` and the other queries pushed a made-up 0 or 1. The fallible words reported a wrong type as an ordinary error the caller could catch. Every `thread` word now raises on a wrong type, as `strings` does.
- **`strings::is_blank` said a string of no-break spaces was not blank.** It stepped a byte at a time, so after decoding a multi-byte space it decoded that space's second byte on its own.
- **`strings::split_n` left an extra value on the stack** when `n` was 0 or less or the delimiter was empty: a `1` between the parts and the status.
- **`strings::pad_left`, `pad_right` and `center` could read past the end of the pad string.** A pad whose only byte was a stray UTF-8 lead byte was copied as the full sequence that byte promised.

- **`pub inline struct` and `pub packed fn` compiled with the modifier dropped.** After `pub`, any declaration accepted `inline` and `stack` and any accepted `packed`. Without `pub` they were already errors. Now `inline` and `stack` must be followed by `fn` and `packed` by `struct` in both cases.
- **An import block skipped anything that was not a function.** A typo such as `fm abs(...)` dropped the declaration without a word. It is now an error, reported once per run of stray tokens. A function with no name is reported as such instead of as "Expected 'fn' after 'pub'".
- **One syntax error was reported as many.** Error recovery consumed whatever it stopped at, and each case caused a cascade:
  - A keyword: the declaration it began was lost, and its name and body were reported as stray top-level tokens.
  - A `}`: the enclosing body lost its end and ran into the next function.
  - A `{`: the broken construct's own `}` closed the enclosing body.

  Recovery now leaves a keyword or `}` for the code around it, including when the token in error is one (`enum E` followed by `fn main`), and drops a broken construct's block whole while still reporting the errors inside it.
- **`pub const` with no name cascaded.** Error recovery skipped ahead past the next `fn` keyword, so the following function's name and closing brace were reported too. It now recovers the way `const` does.
- **An installed package's native library was not found when its module files sat below the package's root.** quadc looked for the package one directory below the packages directory, as `name@version`, but quadpm installs at `<host>/<user>/<repo>@<ref>`, so it looked in the host's directory and never added the package's `lib/` to the link. It now takes the nearest directory above the module that has a `lib/`.
- **`!` and `?` were dropped on a method that shares a builtin's name** (`set`, `get`, `add`, `len`) anywhere but the top of a function body: in a `test`, or inside an `if`, `switch` or loop, `v 0 100 set!` called `set` and ignored its failure. Such a name parses as a builtin, and a builtin took its suffix only there. It now takes it wherever it is written.
- **A method that shares a builtin's name was checked less than any other method**: no argument types, no `!`/`?` rules, and a bare fallible call pushed no status for the `if` that read it. Both forms of method call now go through one check, and one code path for failures.
- **Building an imported module's struct by its bare name switched off the function's own checks**, such as its output count: the construction fell through to the call checks, found no function by that name, and marked the function's stack unpredictable. The three copies of positional construction are now one.
- **A program under any directory named `tests` or `lib` did not see the files beside it.** quadc and quadlsp skipped the directory namespace for every path containing `/tests/` or `/lib/`, a guard for this repository's own test corpus. The rule is now the same everywhere, and §9.7 of the specification states it; the corpus keeps each helper with the test that uses it, and names its test-block files `*_test.qd`. A file a program brings in with `use "file.qd"` is no longer merged a second time as a directory sibling.
- **The embedding API (`qd_build`) loaded one file of each module**, whichever the directory listed first, and looked for a module's `use helper.qd` among the stdlib modules, so a script using `ct` compiled and then failed at run time. It now runs the same module search as quadc: every file of a module, each validated alongside the others, and the script's registered native modules before the installed ones, as the validator already had it.
- **`-g` failed on any program with a function the native calling convention takes**, an `i64` or `f64` one such as `fib`, with `Global is external, but doesn't have external or weak linkage`. Debug info keeps every function stack-based, so the native version was declared and never defined. It is no longer declared under `-g`.
- **`quadc -g -r` crashed after the program had run**, sometimes and for some programs every time, with a segmentation fault in quadc's own teardown: the JIT freed the LLVM context the debug-info builder still pointed into. The builders are released before the JIT takes the context.
- **A module file that `use`s a sibling in the same module** (`use helper.qd`) loaded that sibling twice, since a module is already every file in its directory. Its functions were generated twice, silently as dead code, and under `-g` as a second debug subprogram that failed verification. Each file is loaded once per namespace.
- **A C function imported in the program's own file** got none of what one imported in a module gets: no native bridge, so a caller of it never took the native path. Both go through one declaration.
- **A function's argument types were never checked at run time.** The check codegen emits matched only one-letter type names the language no longer accepts, so every parameter went unchecked: an `any` holding an `i64`, passed on to a `str` parameter, arrived as a string. Where an `any` reaches a parameter of a definite type, the call now checks it, and stops with `Type mismatch for parameter 1 (expected str, got int)`; an `i64` in it widens to an `f64` or `d128` parameter. Calls that pass no `any` check nothing more.
- **A method call converted none of its arguments.** An `i64` passed to an `f64` method parameter was warned about and handed over as it was; it is now converted, as a function call's is. Function and method calls check their arguments in one place.
- **Code generation read type names as written**, so a parameter typed by an alias or by `bool` missed the integer and native fast paths, and the aliases of a C `import`'s signature were not yet known when it was declared. Every type is now resolved once, the aliases first.
- **Installed packages were found by quadc and not by the validator**, which looked in a `cache/` directory quadpm no longer writes, so a namespace two packages declared was never reported. It is now an error naming both packages' full paths.
- **quadc picked an installed version by directory order**, so with two installed it could build against either. The newest is chosen; `-l` pins one, and the validator now honours `-l` too.
- **`qd.json`'s git dependencies were looked for in `~/quadrate/modules` whatever `QUADRATE_PATH` said**, and the language server treated `~/.quadrate/modules`, which nothing writes, as where installed modules live.
- **A full-path import (`use "github.com/user/repo"`) failed as "not found".** It now resolves; the compiler cannot build one yet and says so, naming the namespace to `use`.
- **`io::read` and `io::write` reported their errors as `io::read_bytes` and `io::write_bytes`**, and several `fmt` and `net` messages named the C function rather than the word.
- **A type alias inside an array type**: with `type Score = i64`, a `[]Score` parameter rejected the `[]i64` it is. An alias now resolves through a chain, and inside `[]`, in every position.
- **`import` declarations typed `i8`, `i16`, `bool` or `[]T`** got `any` or a bare pointer in a program's own import block, where a module's got the real type. Every signature, of a function or an import, in the program or a module, now maps its types in one place.
- **`quadlsp` completion and hover** offered `sqrt`, `sin`, `case` and `default`, none of which are builtins or keywords, and missed `nth`, `clone`, `dup2` and others; hover knew about 38 words. Both, and signature help, now read `reference.def`, so every builtin shows its stack effect.
- **Escapes in `const` strings, array literals and `switch` labels.** Compiled code kept `"a\tb"` as a backslash and a `t` in all three; a plain literal, and the interpreter, decoded it. One decoder now serves every position and both tiers.
- **`sizeof<d128>` was 8**, the size of a pointer; it is 16. `sizeof` of a struct now finds it as every other use does.
- **`quadlsp` took seconds per keystroke**: it parsed every `.qd` file beside the open one on each change, and its lint step wrote a copy of the buffer into the shared temp directory, leaked it when the lint failed, and then linted every leaked copy there too. A clean directory now answers in milliseconds, and the lint copy goes in a directory of its own that is always removed.
- **`quadlsp` type completion** read past the end of its description table, so every type from `d128` on showed the next one's description.
- **`make tests` skipped `test_decimal_register`, `test_math_register` and `test_lsp_robustness`**, which were built and registered but missing from the runner's hand-kept list. The runner now asks meson for the list.
- **`make quadmcp` failed to compile**: it left out the generated `version.qd`.
- **`within` and `err` were documented wrongly**: `within` includes both ends, and `err` pushes the message and the code.
- **String interpolation of anything but a string or an integer crashed.** `$"x = {x}"` with an `f64` `x` sent it to `sb::append_int`, which died on its first `mod`; every other type now goes through `cast<str>`.
- **`pub var` exports the global.** `pub` was never read when the global was emitted, so every `var` got internal linkage and nothing outside the LLVM module could reach one. In `--freestanding`, where `pub fn` is deliberately given external linkage so assembly can call it, that left module-level mutable state unusable for the one kind of program that needs it: `examples/kernel` declares its four mutable globals in a `.S` file and reaches them through an FFI address getter and `sys::ld64`/`sys::st64`, though three of them are touched only from Quadrate. The symbol is `qd_global_<name>`, and `tools/check_global_var_linkage.py` (reference suite) pins both directions.
- **A store to a module global hands back what the slot held.** `-> g` wrote the new pointer straight over the old one and released nothing, so every reassignment of a `str` or struct global leaked what it replaced -- §11.2.2 says a place that holds a value owns a reference. It stayed hidden because a `str` global started null and the tests assigned each global once; valgrind cannot see the struct case at all, since the pointer registry still holds the value at exit and reports it reachable, so the `global_var_store` case in the memory suite measures it instead. The release is unconditional: `g -> g` reads through a retain, and that is the reference the store hands back.
- **A `str` global runs its initializer.** `var label = "hello"` compiled clean and the literal was dropped — a refcounted string needs a heap header, which no LLVM static initializer can express, so the global stayed null. Reading it then pushed *nothing*, because `qd_push_s_ref` refuses a null and returns an error nothing checked, so the next instruction died of a stack underflow naming itself: `Fatal error in print: Stack underflow`. String initializers now run in the module-init sequence that already existed for struct globals, and a global holding no string reads as the empty one.
- **A `type` alias no longer launders a sized integer type past the check that rejects it.** `type Byte = u8` then `fn f(b:Byte …)` compiled clean; the rejection ran on the written name, before alias resolution. It now reads through the chain at all five positions that reject one — parameter, return value, module global, cast target and anonymous function — and names both spellings: `'Byte' is an alias for 'u8', a memory-layout type`.
- **`ct::Vec` shared its buffer between stale copies, so a `release` freed memory another live `Vec` still pointed at.** `push` allocated a new `Vec<T>` on every call and returned it, sharing `data` with the value it was called on: the old value stayed valid with its old `len` and its pre-realloc pointer, giving a use-after-free and a double-free reachable without touching `mem`, and an allocation per element. It writes through the receiver now, as `>>field` does, and `pop`, `set` and `reset` — and the same shape in `Deque`, `Queue`, `Map` and `Set` — go with it.
- **`enum E { A = 1_000 }` compiled clean, with the wrong value**: the scanner handed the parser `1` and then an identifier `_000`, read as the next variant. Digit separators are now rejected by name wherever a numeric literal is scanned.
- **The interpreter tier refuses what it does not interpret, by name.** An anonymous function reported a parse error about a method declaration, and a method was accepted with its receiver dropped; both are refused now, before anything is recorded.
- **A `[]T` no longer satisfies a declared `ptr`.** An array could be handed to any of the 54 stdlib functions taking a raw `arr:ptr count:i64` buffer, which then wrote through the `qd_array_t` header. The rule applies to parameters, outputs and struct fields alike; `flag::parse`, `fuzzy::best` and the structs chapter's `Stack` are corrected to `[]T`.
- **An FFI `import` block can spell every type a signature can.** Its parameter list read one identifier after the `:`, so `[]str`, `fn(...)`, `*T` and `mod::T` came apart silently. Fifteen stdlib declarations that said `ptr` over a real array are corrected.
- **A field is checked the same way wherever it is written.** The five field-write sites had five answers; three did no pointer-type check at all. They now share one `fieldValueRejected`.
- **`<<field` reads the field the value's own type names.** With the type unknown the backend took the first struct in the module declaring that name and used its layout, silently returning the wrong value. The validator now records the resolved type on the node; an ambiguous fallback search is reported instead of guessed, and reporting it fails the compile.
- **An unterminated `<` in a type is a parse error.** `Box<` parsed, so the formatter wrote back output that no longer parsed.
- **A struct holding an array field releases it.** The generated destructor stopped at strings and nested structs, leaking 192 bytes an iteration for `struct B { xs:[]i64 }`. The unused second copy of the field walk, `generateStructCleanup`, is deleted, and the memory suite reads `VmHWM` instead of `getrusage(RUSAGE_CHILDREN)`, which hid the leak under 13 MB of floor.
- **An enum value written in binary, and one written with a leading zero.** `parseEnumDeclaration` used `strtoll` at base 0, so `010` was octal and `0b101` depended on the libc. All six such call sites, and `qd_eval`'s tokeniser, now go through one `readIntegerLiteral`.

The compiler's own two literal parsers tested the first character for `'0'`, so a sign hid the radix prefix; both now step over the sign and keep the bound exact at `-0x8000000000000000`.
- **An unterminated `/*` or `"` is a parse error.** Both were accepted in silence, and the formatter re-emitted a `*/` the author never wrote or grew a module name by a newline every pass. The string check now covers every place a string token is consumed.
- **A declared parameter struct type is no longer overwritten by inference.** Inference attributes an unattributable field access to the first parameter, so `fn connect(re:Nfa …)` was recorded as taking a `State` and every correct call was rejected. Inference is now the fallback for a parameter that declared no struct type.

- **A function-pointer type keeps its `(` glued to the `fn`**, which the anonymous-function normaliser was separating, so `g:fn (i64 -- i64)` did not parse.
- **A quote's escaping is judged from the run of backslashes, and only inside a string.** Testing the single character before the quote read `"a\\"` as unterminated and made the formatter hand files back untouched.
- **A nested block comment is read to its own end.** `parseComment` dropped the last character before EOF and the formatter's brace scanners did not nest at all.
- **The formatter no longer drops what shares a line with a block's braces**, which lost the body of `fn one() { 1 print nl`.
- **The formatter takes a block's `{` from the parser instead of guessing**, rather than using the first `{` on the line.
- **A struct or `import` declaration copies out its own text, and only that.** Both copied whole lines, so a declaration sharing a line with what follows carried it along and emitted it twice.
- **The formatter hands back the source when a block's braces do not balance**, instead of scanning to EOF or emitting only a declaration's first line.

## [0.5.0] - 2026-04-16

### Added

- **`inline` function modifier**: functions declared with `pub inline fn` are inlined at every call site via LLVM's `AlwaysInline` attribute. Works at all optimization levels including `-O0`.
- **`sys` standard library module**: zero-overhead inline wrappers for raw memory access (`sys::st8`/`st16`/`st32`/`st64`, `sys::ld8`/`ld16`/`ld32`/`ld64`), x86 I/O ports (`sys::port_in8`/`port_in16`/`port_in32`, `sys::port_out8`/`port_out16`/`port_out32`), and CPU control (`sys::cli`, `sys::sti`, `sys::hlt`).
- **Freestanding compilation** (`quadc --freestanding`): compile without libc for bare-metal targets. Emits `.o` with a `_start` shim using a static runtime context. Rejects hosted-only builtins and most stdlib modules at compile time.
- **Freestanding runtime** (`lib/rt/src/freestanding.c`): minimal no-libc runtime with static context, halt hooks (x86/ARM/AArch64), and value-stack operations. No heap, no I/O.
- **Freestanding-safe `mem` module**: split into `mem.c` (safe subset: `set_byte`, `get_byte`, `copy`, `zero`, `fill`) and `mem_heap.c` (heap-using: `alloc`, `realloc`, `free`). Freestanding builds link only the safe subset.
- **Raw memory builtins** (`__st8`/`__st16`/`__st32`/`__st64`, `__ld8`/`__ld16`/`__ld32`/`__ld64`): zero-overhead store/load lowering directly to LLVM instructions. Internal — use `sys::st8`/`sys::ld8` instead.
- **x86 I/O port builtins** (`__port_in8`/`__port_in16`/`__port_in32`, `__port_out8`/`__port_out16`/`__port_out32`): lower to inline assembly. x86/x86_64 targets only.
- **CPU control builtins** (`__cli`, `__sti`, `__hlt`): lower to single inline assembly instructions.
- **Type alias declarations** (`type` / `pub type`): compile-time type aliases resolved during semantic validation.
- **String interpolation** (`$"hello {name}"`): desugars to `sb::new`/`sb::append`/`sb::finish`.
- **Boolean literal type**: `true`, `false`, `Ok`, `Err` parsed as boolean literals.
- **Build cache**: content-based incremental compilation using FNV-1a hashing. Skips codegen when output is up-to-date.
- **Test coverage** (`quadc --coverage`): function-entry instrumentation with coverage report after test runs.
- **`quaddoc` cross-references**: call graph with `calls`/`calledBy` arrays and hyperlinks.
- **`quadlint` `//nolint` directive**: per-line or per-rule lint suppression.
- **Typed C embedding API**: `qd_pop_i()`, `qd_pop_f()`, `qd_pop_s()`, `qd_pop_p()`, `qd_error_code()`, `qd_error_message()`, `qd_clear_error()`, `qd_context_stack_size()`.
- **`quadpm` semver-aware update**: resolves constraints from `qd.json`, checks git tags, installs newest compatible version.
- **Improved semver conflict detection**: `rangesHaveCommonVersion()` probing across caret/tilde/explicit ranges.
- **`quadmcp` dynamic module list**: loaded from `docs/api/modules.json` instead of hardcoded.
- **Array syntax in signatures**: `[]i64`, `[]f64`, `[]str`, `[]ptr` types.
- **Function pointer syntax in signatures**: `fn(i64 -- i64)` types in struct fields and parameters.
- **Automated AUR package publishing** via SourceHut CI.
- **`cast<i64>`** now supports pointer-to-integer conversion via `uintptr_t`.
- **Bare-metal x86_64 kernel example** (`examples/kernel/`) with GDT, IDT, PIC remapping, PIT timer interrupts, PS/2 keyboard driver, VGA text output, screen scrolling, backspace, and a `> ` shell prompt. Written in pure Quadrate with assembly bootstrap.
- **New examples**: `csvcut`, `mandelbrot`, `brainfuck`.
- **New test suites**: build cache, freestanding compilation, raw memory, type aliases, string interpolation, inline functions (10 test cases).
- **Documentation**: `inline` keyword in specification, keyword reference, quick reference, and function tutorial. AUR installation instructions.

### Changed

- **`quadfmt` rewritten**: AST-based formatting replacing line-based approach. Formatter now preserves the `inline` keyword.
- **Version numbering** derived from git tags instead of a static `VERSION` file.
- **Deduplicated compiler errors**: parsing errors deduplicated by `line:column:message`.
- **Method call resolution**: uses `userFunctions` map instead of mangled name construction, fixing collisions with builtin instruction names.
- **LSP signature formatting**: empty parameter lists no longer produce spurious ` -- `.
- **Benchmarks modernized**: named parameters and operator syntax replacing stack manipulation.
- **CI**: `quadfmt --check` added to Arch, Alpine, and Debian builds.
- `AlwaysInlinerPass` now runs at all optimization levels (including `-O0`).
- `GlobalDCEPass` skipped in freestanding mode to preserve `pub` functions callable from assembly.
- Target triple and data layout set early in code generation for correct struct layouts on cross-compilation targets.
- Stack struct fields `capacity` and `size` changed from `size_t` to `uint64_t` for consistent layout across 32-bit and 64-bit targets.
- Freestanding mode: `pub` functions get external linkage so they survive DCE and can be called from assembly.
- `make format` now formats both C++/H files (via `clang-format`) and `.qd` stdlib/example files (via `quadfmt -w`).

### Fixed

- `<` operator code generation edge case.
- `cast<i64>` on pointer values no longer crashes with "Cannot cast type to integer".
- Compile-time stack path for `st8`/`ld8` family: fixed a latent bug where these builtins would read from the wrong stack in native functions.
- Formatter output validation distinguishes source parse errors from formatter bugs.
- i386 data layout patched with `i64:32:64` to match the System V ABI alignment.

### Removed

- `lineWidth` formatting option from `quadfmt`.
- `pkg/deploy-aur.sh` deploy script (replaced by CI-based AUR publishing).
