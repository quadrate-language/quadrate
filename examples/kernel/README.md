# kernel

A bare-metal i686 multiboot kernel written in **pure Quadrate**.

This is the proof-of-concept for `quadc --freestanding`. There's no libc,
no heap, no I/O — the kernel writes directly to the VGA text buffer at
`0xB8000` from Quadrate code, using the `store_u16` builtin and the
freestanding-safe subset of the `mem` module. The only non-Quadrate code
is `boot.S` (multiboot header + stack setup) — a hardware constraint,
since multiboot entry runs with no stack and assembly is the only thing
that can run before one is set up.

## What it does

Boots under any multiboot1 loader (GRUB, `qemu -kernel`), prints
`Hello, Quadrate kernel!` on the top row of the VGA text screen, then
halts forever.

## Build

```sh
make           # produces kernel.elf — multiboot-compliant 32-bit ELF
make iso       # produces kernel.iso — bootable on real hardware via GRUB
```

Build deps:

- `clang` with built-in i686 cross-compilation (any modern clang)
- `ld` (GNU binutils, for `-m elf_i386`)
- `xorriso` + `grub-mkrescue` (only for `make iso`)

The Makefile assumes the Quadrate repo is built — the kernel links
against `lib/rt/src/freestanding.c` and `lib/mem/src/mem.c`, and uses
`build/release/cmd/quadc/quadc`. Adjust `REPO_ROOT` in the Makefile if
this directory is moved.

## Run

```sh
make run       # boots kernel.elf in QEMU directly (qemu -kernel)
make run-iso   # boots kernel.iso (full GRUB → kernel boot path)
```

Needs `qemu-system-i386`. Both targets use `-display curses` so QEMU
runs in the terminal — press `Esc, x` to quit, or `Esc, 2 quit` for the
full QEMU monitor exit.

Expected output (top-left of the screen):

```
Hello, Quadrate kernel!
```

## How it fits together

```
┌─────────────────┐  multiboot loader (GRUB / qemu -kernel)
│   _kernel_entry │  ◄─── boot.S sets ESP, calls _start
└────────┬────────┘
         │
┌────────▼────────┐  generated by quadc --freestanding
│      _start     │  ── calls qd_freestanding_halt() if user fn returns
└────────┬────────┘
         │
┌────────▼────────┐  user's pub fn _start( -- ) in kernel.qd
│  usr_..._start  │  ── direct VGA writes via store_u16 + mem::set_byte
└────────┬────────┘
         │
┌────────▼────────┐
│  VGA text mode  │  visible on screen
└─────────────────┘
```

Where the VGA writes resolve:

- `store_u16` is a Quadrate builtin: codegen lowers it directly to a
  `store i16` LLVM instruction. No runtime call, no library function.
- `mem::set_byte` is a freestanding-safe FFI call into
  `libmem-freestanding.a` — same `mem.c` source as the hosted stdlib,
  but built without any heap-using siblings (`mem_heap.c` is not linked).

The `qd_freestanding_ctx` global (defined in `lib/rt/src/freestanding.c`)
holds a statically-allocated value stack — no `malloc`. The default
`qd_freestanding_halt` is a `cli; hlt` loop, but it's a weak symbol so
you can override it (e.g. to print "PANIC" to VGA before halting).

## Source files

| File           | Role                                                          |
| -------------- | ------------------------------------------------------------- |
| `kernel.qd`    | Quadrate program: `_start`, VGA writes via `mem::set_byte` and `store_u16` |
| `boot.S`       | Multiboot1 header, stack setup, jump to `_start`              |
| `linker.ld`    | Loads at 1 MiB, places multiboot header in first 8 KiB        |
| `grub.cfg`     | GRUB menu entry that boots the kernel                         |
| `Makefile`     | Wires it all together; includes `freestanding.c` and `mem.c`  |

## Where to go from here

This kernel is intentionally minimal — single-thread, no interrupts,
no paging, no allocator, halts after one screen write. To grow it:

- **Keyboard input**: hook IRQ 1, write a PS/2 driver and expose it as
  an FFI module (e.g. a small `kbd.c` with a `read_char(qd_context*)`
  function imported via `import "kbd.o" as "kbd" { ... }`).
- **Heap**: write a simple bump allocator in C, expose as `mem::alloc`
  to override the missing freestanding symbol. With a heap, you can
  start using `strings` and `sb` (link them carefully — they expect
  more stdlib than just `mem`).
- **64-bit long mode**: rewrite `boot.S` to set up GDT/paging and switch
  to long mode; build the kernel with `--target=x86_64-unknown-none-elf`.
- **Real screen**: drop VGA text mode, set up a framebuffer via VBE or
  multiboot's framebuffer tag.

None of these require language changes — they're all just C/asm shims
exposed via Quadrate's FFI.
